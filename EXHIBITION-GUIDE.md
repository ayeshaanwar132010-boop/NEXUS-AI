# NEXUS AI Exhibition Runbook

## One-minute introduction

“NEXUS AI is a local-first autonomous-workflow prototype. It demonstrates how an objective can be planned, split across specialist agent roles, supported by persistent memory, executed under explicit controls, verified, and recorded in an audit trail. This build uses deterministic logic so visitors can inspect predictable behavior without depending on a paid model API.”

## Five-minute live demo

- **00:00–00:45 | Command Center:** introduce the platform and its current local status.
- **00:45–01:30 | Intelligence Core:** explain the orbital visualization as a view of system components, not a claim of consciousness.
- **01:30–02:15 | Memory:** create and search a fictional memory, then refresh to show persistence.
- **02:15–03:15 | Planning and agents:** create a small objective, show task dependencies and agent responsibilities.
- **03:15–04:15 | Execution and verification:** run the local demo and show honest state changes and audit events.
- **04:15–05:00 | Automation and safety:** test a paused/controlled rule in simulation and explain that no external action is sent.

## Backup plan

If Wi-Fi is unavailable, the local application should still run once dependencies are installed. Keep screenshots and a short screen recording available as backup, but identify them as recordings rather than live execution. If an API request fails, show the error state and explain what failed rather than claiming success.

## Exhibition safety checklist

- Use fictional data only.
- Keep the backend bound to localhost unless deployment has been secured.
- Do not display API keys, passwords, personal records, or private documents.
- Do not describe simulated email/report/API actions as real submissions.
- Verify the backend and frontend before opening the demo.
- Keep the README and source code available for technical questions.
